Based on what the app actually does: AI-generated text/images from user-written journal entries, no user-to-user interaction, no user-generated content shared publicly by default (referral links share only a poster the user chose to share). Answer against the **app's own designed behavior** — the honest caveat below applies to any AI-generation app.

| Question | Suggested answer | Why |
|---|---|---|
| Violence — realistic/cartoon | None | The app doesn't prompt for or feature violent themes. Genre options include "Action" and "Horror," which could plausibly generate mild dramatic/tense imagery (e.g., an action-movie poster), but not graphic violence, gore, or blood. |
| Sexual content / nudity | None (designed behaviour) — see "Safeguards against restricted AI output" below | Not a feature, and the app is general-audience. Safeguards that exist in the code today: server-side keyword blocklist on all user text/prompts, positive "fully clothed / non-sexual / adults only in visuals" rules in every script and storyboard instruction, Gemini `safetySettings`, a hard stop on any provider content refusal, no unfiltered last-resort image provider, face-photo moderation (Nemotron) with ownership-checked references. **Not yet in place:** an in-app report button (planned). ## Safeguards against restricted AI output (what the code does today)
Verified against the code on branch `fix/content-safety-hotfix`; update this list when the planned items ship.

| Layer | What it does | Where |
|---|---|---|
| Input blocklist | English + Hebrew keyword/phrase list (explicit sexual wording, nudity, minors next to sexual wording). Applied server-side to the journal entry, the storyboard script and every image prompt, **before** any quota is spent or any model is called. A hit returns a localized message (`CONTENT_BLOCKED`). | `lib/content-blocklist.js`, `generate-script.js`, `generate-storyboard.js`, `generate-poster.js` |
| Prompt length / markup | Image prompts are stripped of markup and capped at 1500 characters (direct API calls included). | `generate-poster.js` |
| Positive safety rule | Every script and storyboard instruction tells the model: fully clothed in modest attire, non-sexual scenes, only adults in the visuals, explicit source material rewritten tastefully. | `lib/content-safety.js` → `lib/agent.js`, `generate-storyboard.js` |
| Gemini safety settings | Explicit `safetySettings` on every Gemini text call (sexual content blocked at medium and above). | `lib/story-service.js`, `generate-storyboard.js` |
| Refusal is final | If a provider refuses the content (Cloudflare NSFW filter, OpenRouter/Grok/Gemini safety block, Gemini script block), the request ends with a placeholder and `CONTENT_REFUSED`; it is **never retried on another provider**, nothing is charged. | `lib/content-safety.js`, `generate-poster.js`, `lib/story-service.js` |
| No unfiltered fallback | Pollinations (anonymous, unfiltered) was removed from every image chain. | `generate-poster.js` |
| Output image check | Every generated image (poster, comic panel, Star Yourself image, Character Sheet) is classified by a safety model before it is shown or stored (primary: NVIDIA Nemotron content-safety, verified on real samples incl. an explicit one; backup: Gemini 2.5 Flash-Lite through our AI gateway with no-training routing). Every image the primary calls safe is then put to a SECOND, independent question — does it contain nudity or sexualized content, or any sexualized depiction of a person who looks like a minor? — and is shown or stored only if both agree. An unsafe verdict shows a placeholder instead and nothing is charged. If no checker can answer, the image is not shown (retry). Uploads to storage accept only bytes our own generator just approved; anything else is never stored. | `lib/image-check.js`, `generate-poster.js`, `upload-panel.js`, `upload-character.js` |
| Text output check | Every generated script and comic storyboard passes the keyword blocklist on its OUTPUT and then an automatic safety classifier (Gemini Flash-Lite through the AI gateway, strict JSON verdict) — **all genres**. A held-back output is regenerated ONCE with a safety reminder; held back again → "content refused"; the quota is returned in every refusal. If the classifier cannot answer: ROMANCE and HORROR return "safety check unavailable" (nothing is returned); other genres are returned on the blocklist result alone and the degradation is counted. Horror: violence is written implied and non-graphic. Each paid check has its own daily budget and circuit, so one cannot switch off another. | `lib/text-check.js`, `generate-script.js`, `generate-storyboard.js`, `lib/content-safety.js`, `lib/budget.js` |
| Apparent-minor screen | At "Star Yourself" upload an automatic best-effort check rejects a photo only when it CLEARLY appears to show a child; unsure or any failure allows it. It is **not age verification** and cannot confirm anyone's age or identity; the 18+ checkbox and the consent are the actual rule. Never describe it as age verification. | `lib/minor-screen.js`, `upload-character.js` |
| In-app reporting | A "Report" control on every poster, comic panel and reel (reasons: sexual/nudity, violent/disturbing, other). The reporter's own report hides the image immediately and a team alert is sent; the image moves to a private storage area. A report stores a one-way pseudonymous reporter id, the image's storage key and the reason (up to 90 days) — never the image, text or an IP. The home-page gallery samples (cards, genre view, lightbox, reel lightbox) have the same control as a lighter flow: the item is hidden for that user only and the team is alerted with the file name, then removes it in a deploy (the app never claims global removal for these). | `pages/api/report-content.js`, `lib/report.js`, `lib/quarantine.js`, `components/ReportButton.jsx` |
| Age rules | Terms: 13+ overall (`constants/modalData.js` §7). "Star Yourself" (face upload): **18+ only**, confirmed by a separate "I am 18 or older" checkbox that the server also requires (`adult: true`, `pages/api/upload-character.js`, `ADULT_REQUIRED`). This is a self-declaration — it is **not** age verification and must never be described as such. | `components/CharacterModal.jsx`, `upload-character.js` |
| Face photos | Selfie moderation (Nemotron, fail-closed) at upload; the reference used for generation must be the caller's own stored character, not an arbitrary URL. | `lib/identity.js`, `upload-character.js` |
| Diagnostics | Each generated image logs provider, panel index and comic id (no prompt, no image, no user text). | `generate-poster.js` |

**Claim these only once deployed:** the output image check (branch `fix/content-safety-output-check`, merged) and the in-app Report control (branch `feat/content-report`). The Report control's takedown needs the private quarantine bucket configured (`R2_QUARANTINE_BUCKET_NAME`); without it a report only hides the image in the app and alerts the owner to remove the object manually — do not describe it as quarantined until that bucket exists. Not implemented: blocking or banning users (the app has no user-to-user interaction), and a public moderation queue.

## Honest caveat to flag for yourself when filling this out
The journal-entry text field and the resulting AI-generated script/poster/comic are **free-form and AI-generated** — while the app doesn't design for or encourage mature themes, a user *could* type something that leads the AI to generate borderline content (this is true of essentially any generative-AI app with free text input). IARC's questionnaire is generally answered based on the app's designed/intended content rather than exhaustively policing what a generative model could theoretically produce, but it's worth being aware of this distinction if a question is phrased in a way that asks about content the app could ever produce, rather than what it's designed to produce. If you want extra safety margin, mention in the questionnaire's free-text notes (if offered) the safeguards listed above. Be precise: generated images are not yet classified after generation, and there is no in-app report button yet.

## Mismatches to resolve before the appeal (flagged, not decided)

A 13–15 year old is allowed by the Terms but outside the declared audience. Either declare 13+ (then the "teens" obligations of the AI-generated-content and UGC policies apply fully) or raise the Terms minimum age.
2. **Subscription clause in the Terms (web copy):** "purchasing a paid subscription requires 18+ or guardian approval" — correct for the website; the Android build hides it together with all pricing text.
3. **Data safety form:** `data-safety.md` no longer declares Financial info or Stripe (no payment provider is live and the Android app has no purchase flow). Mirror that in Play Console by hand; re-add it if a provider goes live.
4. **Store listing screenshots:** none of the five phone screenshots or the feature graphic shows the old style name or any price (checked: 01, 02, 04, 05 and the feature graphic; 03 and the three captioned images were not opened). Screenshot 01 shows sample posters with real people's faces — confirm you hold their consent.
